# Security

Bluetooth playback uses only the connected, paired device's currently addressed BlueZ MediaPlayer1. Device ownership, adapter, object path and status are revalidated for every action; multiple matching players are rejected. Only toggle/next/previous are exposed, with no arbitrary D-Bus methods, paths, pairing changes, seeking or media URLs. Track text is rendered as React text; remote artwork remains bounded by the existing frame limit and PNG/JPEG allowlist. Source changes invalidate old artwork and metadata.

2026-10-10 dependency audit: updated the locked transitive source-map-js dependency from 1.2.1 to 1.2.2 for [GHSA-68fv-2mgg-jv7q](https://github.com/advisories/GHSA-68fv-2mgg-jv7q). The production audit now reports zero known vulnerabilities. Direct dependency ranges and backend permissions did not change. Local Bluetooth QA images contain device identifiers and are ignored alongside the raw screenshots.

Bluetooth discovery owns only its own short-lived session. Device responses expose a bounded metadata allowlist and do not expose pairing keys or arbitrary D-Bus object paths. Unpairing requires an exact known paired address and an explicit confirmation; the UI provides a separate confirmation before sending the request. Automated tests use fake devices rather than deleting user pairings. Pairing delegates to the installed native agent and does not automatically approve or trust a device.

Refresh preferences use existing loopback Host/origin checks and private durable saves. Only bounded integer music/contact intervals are accepted; the API cannot change paths, subscribe to arbitrary destinations or launch commands. Linux saves flush both file data and the directory entry before returning success.

Never commit SSH passwords, private keys, tokens, browser data, or private vehicle information. The harness uses interactive SSH authentication or an existing SSH agent and intentionally has no password-file option. Keep raw captures under review and redact sensitive values before sharing them.

Phonebook data is read through BlueZ PBAP only for one already-paired, connected phone, with the phone's contact-sharing permission. Names and phone numbers stay in the Pi service's bounded memory cache and local loopback responses. Temporary transfer files use a private temporary directory and are deleted; raw contact screenshots remain ignored and local. Android USB recovery validates a unique AOA device and existing character-device access; it never invokes sudo or resets a USB hub.

Pi layout settings are saved atomically in a private 0600 file, through the existing loopback API and Host/origin restrictions. Only known shortcut IDs and complete validated ordering lists are accepted; the API retains its 4096-byte JSON limit. Essential navigation shortcuts cannot be removed. Layout data never contains contacts, credentials, images, network addresses or executable commands.

Quit uses an argument-free, Pi-host-only application-quit action and the installed runtime's fixed quit_hudiy command. It does not expose arbitrary process termination or shell execution. Pending navigation/USB reopening is canceled, and the host waits for runtime disconnection before ending its own service. Saved configuration and next-boot autostart are preserved.
Physical brightness writes only the unique existing kernel backlight using current user permissions; no root or permission changes are introduced. Requests are integers 5–100 and saved privately. Native OBD configuration changes accept only a currently paired Serial Port address/channel, preserve unrelated configuration, and use the existing runtime reload. Mode 01 queries are correlated, bounded read-only requests through that runtime.

Automatic Bluetooth reconnect stores only up to 16 explicitly selected paired addresses in a private local file, revalidates pairing and limits attempts to every 30 seconds. It does not pair, trust or expose devices publicly. HFP call control matches one powered/online oFono modem to one connected paired BlueZ device, requires a separate UI number confirmation before Dial, and revalidates calls before Answer/Hangup/Muted changes. Current call metadata remains in memory; no calls are made by startup or automated tests. No phone numbers or call paths are saved in preferences or logs. Tests cover malformed numbers, unpaired/ambiguous modems, path injection and existing/multiple calls.
# Car Wi-Fi and radio-output controls

Wireless settings expose no network passwords and preserve the existing protected native hotspot credentials. Enabling is an explicit confirmed Pi-only action and may interrupt the current Wi-Fi connection; it is not enabled automatically during deployment. Native wireless/OBD file edits share a lock and roll back on failed restart scheduling. No firewall or OS access changes are made.

Automatic OBD monitoring runs only in the trusted Pi projection host and follows the native runtime's real OBD connection. It uses the existing six read-only Mode 01 queries, owns no extra RFCOMM connection and performs no pairing or adapter reset. Polling failures retry at most every 30 seconds; disconnect clears stale readings/history. Manual Stop and serial selection override monitoring. Audio receiver pairing/selection is not a prerequisite. No new permissions, dependencies, remote endpoint or external backend rules are introduced.

Projection Day/Night controls accept only Common/Day/Night and a boolean native dark-mode preference. Fixed documented API messages are version-gated for day/night, serialized with native lifecycle actions and refused while unavailable/closing. Private saving precedes sending; send failure restores old saved options and attempts to restore the prior explicit mode. No arbitrary Protobuf message IDs, native actions or settings paths are accepted. Legacy preferences leave native appearance unchanged until selected; explicit choices are replayed after reconnection. Screenshot evidence containing map location remains local and ignored. No new OS permissions, network exposure or dependency is added.

The radio preference stores only one validated paired A2DP receiver address in a private atomic file. PBAP phones are excluded. Routing uses only the selected receiver's observed BlueZ sink and the existing equalizer/echo streams identified by matching node.link-group ownership. Fixed pactl argument arrays have bounded timeouts; missing/ambiguous chains fail without moving other streams. No pairing, playback, recording or arbitrary sink/path/command input is accepted.
